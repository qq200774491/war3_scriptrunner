# 云脚本测试框架

`mls-sim test` 在本地启动隔离的云脚本房间，并在独立 Lua VM 中执行测试文件。测试代码只能发送原始平台事件和读取 `MsSendMlEvent` 的下发结果；它不会提供或模拟游戏客户端的可靠消息框架。

## 快速开始

```powershell
mls-sim.exe test G:\Sourcetree\DaiHaoN\server\tests
mls-sim.exe test G:\Sourcetree\DaiHaoN\server\tests --reporter json
```

仓库内的最小示例：

```powershell
mls-sim.exe test examples\cloud-tests\tests
```

无 `test` 子命令时，程序仍按原方式启动 GUI 和 HTTP Bridge。

## CLI

```text
mls-sim.exe test <TEST_DIR>
  [--script-dir <DIR>] [--manifest <FILE>]
  [--test <GLOB>]... [--tag <TAG>]...
  [--list-tests] [--fail-fast] [--jobs <N>]
  [--reporter <console|compact|json>] [--out <FILE>]
  [--log-tail <N>]
  [--discovery-timeout <S>] [--startup-timeout <S>]
  [--case-timeout <S>] [--event-timeout <S>]
```

- `--test` 支持大小写敏感的 `*` 和 `?`，多个条件之间为 OR。
- `--tag` 可重复，测试必须包含全部指定标签。
- `--list-tests` 只加载测试文件完成注册，不创建云房间。
- `--jobs` 设置并行执行的测试用例数，默认为 `1`，必须大于 `0`。Agent 和 CI 推荐先使用 `--jobs 4`。
- `--fail-fast` 会强制有效并行数为 `1`：执行到首个失败用例后不再调度后续用例。
- `--out` 写入完整 reporter 内容，不再向 stdout 重复输出。
- 退出码 `0` 表示通过，`1` 表示测试失败，`2` 表示参数或发现错误，`3` 表示 runner 内部错误。

## 目录与清单

runner 递归发现 `*_test.lua`，按相对路径排序，并跳过隐藏目录、`helpers/`、`fixtures/` 和 `meta/`。

```text
tests/
  mls-test.json
  message_test.lua
  helpers/protocol.lua
  fixtures/handlers.lua
  meta/mls_test.lua
```

`mls-test.json` 示例：

```json
{
  "script_dir": "..",
  "cloud_bootstrap": ["fixtures/handlers.lua"],
  "room": {
    "mode_id": 0,
    "players": [{"index": 0, "name": "Player_0"}]
  },
  "timeouts": {
    "discovery": 2.0,
    "startup": 5.0,
    "case": 15.0,
    "event": 2.0,
    "shutdown": 1.0
  }
}
```

清单中的路径相对清单目录。`cloud_bootstrap` 在生产 `main.lua` 之后、`_roomloaded` 之前执行。每个测试 invocation 使用新的房间和临时存档目录，不读取模拟器的普通 `config.json` 或历史 archives。

脚本目录优先级为 `--script-dir`、清单 `script_dir`、测试目录中的 `main.lua`、测试目录父级中的 `main.lua`。

## 测试 DSL

```lua
TEST_CASE('raw event round trip', '[event][example]', function(ctx)
    local client = ctx:client(0)

    REQUIRE_EQ(client:send('echo_req', 'hello'), 0)
    local response = client:waitEvent({name = 'echo_res'})

    REQUIRE(response)
    CHECK_EQ(response.data, 'hello')
end)
```

断言包括 `CHECK`、`REQUIRE`、`CHECK_EQ/NE/NEAR`、对应的 `REQUIRE_*`、`CHECK_THROWS`、`CHECK_NOTHROW`、`FAIL_CHECK`、`FAIL`、`SKIP`、`SUCCEED`、`INFO` 和 `CAPTURE`。

- `CHECK` 失败后继续执行；`REQUIRE` 和 `FAIL` 终止当前 invocation。
- 表的 EQ/NE 使用循环安全、键顺序无关的深比较。
- `INFO` 和 `CAPTURE` 会附加到后续失败信息。
- `print` 被捕获到测试报告，不污染 JSON stdout。

## SECTION

`SECTION(name, body)` 使用 Catch2 式路径重跑。每条叶路径会重新加载测试文件并创建新的云房间、测试 VM 和临时存档，因此兄弟 SECTION 不共享服务端全局表、缓存或定时任务。

SECTION 按声明顺序深度优先执行。重跑时 SECTION 布局变化会令测试失败；单个测试最多展开 1024 条 invocation。

## 并行执行

并行调度的单位是完整的 `TEST_CASE`。每个 worker 拥有独立的房间、云脚本 Lua VM、测试 Lua VM 和临时存档目录，用例之间不共享云端全局状态。单个用例内的 SECTION 依赖前一次 invocation 发现叶路径，因此仍在同一 worker 内串行展开。

worker 只返回结构化结果，reporter 由主线程按测试发现顺序统一输出。因此 console、compact 和 JSON 不会因完成先后而乱序，测试脚本的 `print` 与云日志也不会混入 JSON stdout。

并行数会同时增加房间线程、Lua VM 和临时存档的资源占用。在当前 DaiHaoN 套件上，4 路并行是速度与资源消耗较均衡的设置；继续提高并行数通常只在用例数量和单例耗时足够大时有效。

## 原始客户端接口

```lua
local client = ctx:client(0)
local now = client:now()
local errnum = client:send('event_name', 'raw string')
local events = client:poll()
local event = client:waitEvent({name = 'response_name', timeout = 1.0})
local removed = client:clearEvents()
```

`now` 是当前测试 invocation 的单调秒数，同一 invocation 内所有 client 共享时钟起点。它只适合计算测试等待的耗时与固定截止时间，不表示 Unix 时间。`client.eventTimeout` 是当前用例生效的默认事件等待秒数，供需要在多次 `waitEvent` 间共享同一总预算的 helper 使用。事件字段为 `timestamp`、`playerIndex`、`name` 和 `data`。`waitEvent` 会保留名称不匹配的事件；正常超时返回 `nil`，房间异常则抛出测试错误。

需要模拟服务器下发延迟时，可以在发送请求前设置当前测试房间的统一延迟：

```lua
ctx:setServerResponseDelay(0.1)
```

参数必须是非负有限秒数，默认值为 `0`。该设置只作用于此后由云脚本调用 `MsSendMlEvent` 产生的下发事件；云脚本线程不会为此阻塞，同一房间内这些事件仍按原调用顺序送达。把延迟重新设为 `0` 不会让新事件越过已经进入延迟队列的事件。每个测试 invocation 使用独立房间，因此设置不会泄漏到其他用例。

生命周期必须通过宿主接口触发，而不是发送以下划线开头的普通事件：

```lua
ctx:playerLeave({index = 0, reason = 'test'})
ctx:playerJoin({index = 0, name = 'Player_0', reason = 'test'})
ctx:playerExit({index = 0, reason = 'test'})
```

这些接口不提供 JSON、分片、补发、请求 ID 或回执状态机。需要测试某个线协议时，应在测试 helper 中独立编解码，再显式逐帧调用 `send`。

## Reporter

- `console`：逐 invocation 输出结果、失败详情、测试输出和云日志尾部。
- `compact`：使用 `file:line` 单行失败格式，适合 Agent 和 CI。
- `json`：stdout 只输出一个 `schema_version = 1` 的 JSON 文档。

JSON 包含测试用例、SECTION invocation、断言、失败上下文、耗时和失败用例的云日志尾部。测试与数组顺序稳定，时间字段允许变化。

## LuaLS

可将 [mls-test-api.lua](mls-test-api.lua) 加入测试项目的 LuaLS 工作区，或按项目结构放入不参与测试发现的 `tests/meta/` 目录。

本测试框架只验证本地云脚本模拟行为，不能替代 Warcraft III 游戏内测试或真实平台验证。
