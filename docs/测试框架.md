# 云脚本测试框架

`mls-sim test` 在本地启动隔离的云脚本房间，并在独立 Lua VM 中执行测试文件。测试代码只能发送原始平台事件和读取 `MsSendMlEvent` 的下发结果；它不会提供或模拟游戏客户端的可靠消息框架。

二进制位置：本仓库 `mls-sim-rs\target\release\mls-sim.exe`（本机为 `G:\Sourcetree\war3_mls\mls-sim-rs\target\release\mls-sim.exe`），由 `mls-sim-rs/` 目录下 `cargo build --release` 产出。它不会加入 PATH，下文命令中的 `mls-sim.exe` 都应替换为该完整路径或先 `cd` 到该目录。

## 快速开始

```powershell
G:\Sourcetree\war3_mls\mls-sim-rs\target\release\mls-sim.exe test G:\Sourcetree\DaiHaoN\server\tests
G:\Sourcetree\war3_mls\mls-sim-rs\target\release\mls-sim.exe test G:\Sourcetree\DaiHaoN\server\tests --reporter json
```

仓库内的最小示例：

```powershell
mls-sim.exe test examples\cloud-tests\tests
```

无 `test` 子命令时，程序仍按原方式启动 GUI 和 HTTP Bridge。

## CLI

```text
mls-sim.exe test <TEST_DIR>
  [--script-dir <DIR>] [--manifest <FILE>]
  [--test <GLOB>]... [--tag <TAG>]...
  [--list-tests] [--fail-fast] [--jobs <N>]
  [--reporter <console|compact|json>] [--out <FILE>]
  [--log-tail <N>]
  [--discovery-timeout <S>] [--startup-timeout <S>]
  [--case-timeout <S>] [--event-timeout <S>]
```

- `--test` 支持大小写敏感的 `*` 和 `?`，多个条件之间为 OR。
- `--tag` 可重复，测试必须包含全部指定标签。
- `--list-tests` 只加载测试文件完成注册，不创建云房间。
- `--jobs` 设置并行执行的测试用例数，默认为 `1`，必须大于 `0`。Agent 和 CI 推荐先使用 `--jobs 4`。
- `--fail-fast` 会强制有效并行数为 `1`：执行到首个失败用例后不再调度后续用例。
- `--out` 写入完整 reporter 内容，不再向 stdout 重复输出。
- 退出码 `0` 表示通过，`1` 表示测试失败，`2` 表示参数或发现错误，`3` 表示 runner 内部错误。

## 目录与清单

runner 递归发现 `*_test.lua`，按相对路径排序，并跳过隐藏目录、`helpers/`、`fixtures/` 和 `meta/`。

```text
tests/
  mls-test.json
  message_test.lua
  helpers/protocol.lua
  fixtures/handlers.lua
  meta/mls_test.lua
```

`mls-test.json` 示例：

```json
{
  "script_dir": "..",
  "cloud_bootstrap": ["fixtures/handlers.lua"],
  "room": {
    "mode_id": 0,
    "global_archive_api": true,
    "players": [{"index": 0, "name": "Player_0"}]
  },
  "timeouts": {
    "discovery": 2.0,
    "startup": 5.0,
    "case": 15.0,
    "event": 2.0,
    "shutdown": 3.0
  }
}
```

清单中的路径相对清单目录。`cloud_bootstrap` 在生产 `main.lua` 之后、`_roomloaded` 之前执行。每个测试 invocation 使用新的房间和临时存档目录，不读取模拟器的普通 `config.json` 或历史 archives。测试房间的 ScriptArchive、CommonArchive 与 ReadArchive 只在内存中往返：`MsSave*`/`MsSet*` 不会像 GUI 或桥接房间那样在每次调用、玩家退出和房间关闭时同步写入磁盘文件，`MsGet*` 读取的始终是同一份内存值；因此临时存档目录中不会出现可供人工查看的 JSON，需要原文时用云脚本侧的 `MsGetScriptArchive` 或测试夹具取回。

`timeouts.shutdown` 覆盖用例结束后等待房间线程退出的时间；房间关闭路径已不含磁盘写入，但仍要等待当前 Lua 调用返回与 VM 析构，机器繁忙时建议 3 秒以上。

`room.global_archive_api` 缺省为 `true`：每个测试 invocation 拥有独立的全局存档（`MsGA*` / `MsBroadcast`），用例之间互不可见；同一用例通过 `ctx:createRoom()` 创建的房间共享这份 GA。设为 `false`，或给用例加上 `[no-ga]` 标签，该用例内全部房间以“旧平台”方式创建——这些全局函数不存在，用于验证云脚本的能力探测与降级路径。

脚本目录优先级为 `--script-dir`、清单 `script_dir`、测试目录中的 `main.lua`、测试目录父级中的 `main.lua`。

## 测试 DSL

```lua
TEST_CASE('raw event round trip', '[event][example]', function(ctx)
    local client = ctx:client(0)

    REQUIRE_EQ(client:send('echo_req', 'hello'), 0)
    local response = client:waitEvent({name = 'echo_res'})

    REQUIRE(response)
    CHECK_EQ(response.data, 'hello')
end)
```

断言包括 `CHECK`、`REQUIRE`、`CHECK_EQ/NE/NEAR`、对应的 `REQUIRE_*`、`CHECK_THROWS`、`CHECK_NOTHROW`、`FAIL_CHECK`、`FAIL`、`SKIP`、`SUCCEED`、`INFO` 和 `CAPTURE`。

- `CHECK` 失败后继续执行；`REQUIRE` 和 `FAIL` 终止当前 invocation。
- 表的 EQ/NE 使用循环安全、键顺序无关的深比较。
- `INFO` 和 `CAPTURE` 会附加到后续失败信息。
- `print` 被捕获到测试报告，不污染 JSON stdout。

## SECTION

`SECTION(name, body)` 使用 Catch2 式路径重跑。每条叶路径会重新加载测试文件并创建新的云房间、测试 VM 和临时存档，因此兄弟 SECTION 不共享服务端全局表、缓存或定时任务。

SECTION 按声明顺序深度优先执行。重跑时 SECTION 布局变化会令测试失败；单个测试最多展开 1024 条 invocation。

## 并行执行

并行调度的单位是完整的 `TEST_CASE`。每个 worker 拥有独立的房间、云脚本 Lua VM、测试 Lua VM 和临时存档目录，用例之间不共享云端全局状态。单个用例内的 SECTION 依赖前一次 invocation 发现叶路径，因此仍在同一 worker 内串行展开。

worker 只返回结构化结果，reporter 由主线程按测试发现顺序统一输出。因此 console、compact 和 JSON 不会因完成先后而乱序，测试脚本的 `print` 与云日志也不会混入 JSON stdout。

并行数会同时增加房间线程、Lua VM 和临时存档的资源占用。在当前 DaiHaoN 套件（300 用例）上，20 逻辑核机器 `--jobs 8` 约 9 秒、`--jobs 4` 约 17 秒、串行约 50 秒；继续提高并行数通常只在用例数量和单例耗时足够大时有效。

## 延迟特性

房间线程的命令队列在有命令入队时会立即唤醒事件循环（`CommandSender` 发送后通知 `WakeSignal`），空闲时最长等待 50 毫秒只作为延迟投递队列的兜底；测试 VM 的 `waitEvent` 以 1 毫秒间隔检查下发事件。因此单次请求往返约 1–2 毫秒，单用例固定开销（建房、加载脚本与夹具、销毁）约 80 毫秒。用例耗时主要由请求数量和显式等待决定。

## 原始客户端接口

```lua
local client = ctx:client(0)
local now = client:now()
local errnum = client:send('event_name', 'raw string')
local events = client:poll()
local event = client:waitEvent({name = 'response_name', timeout = 1.0})
local removed = client:clearEvents()
```

`now` 是当前测试 invocation 的单调秒数，同一 invocation 内所有 client 共享时钟起点。它只适合计算测试等待的耗时与固定截止时间，不表示 Unix 时间。`client.eventTimeout` 是当前用例生效的默认事件等待秒数，供需要在多次 `waitEvent` 间共享同一总预算的 helper 使用。事件字段为 `timestamp`、`playerIndex`、`name` 和 `data`。`waitEvent` 会保留名称不匹配的事件；正常超时返回 `nil`，房间异常则抛出测试错误。

需要模拟服务器下发延迟时，可以在发送请求前设置当前测试房间的统一延迟：

```lua
ctx:setServerResponseDelay(0.1)
```

参数必须是非负有限秒数，默认值为 `0`。该设置只作用于此后由云脚本调用 `MsSendMlEvent` 产生的下发事件；云脚本线程不会为此阻塞，同一房间内这些事件仍按原调用顺序送达。把延迟重新设为 `0` 不会让新事件越过已经进入延迟队列的事件。每个测试 invocation 使用独立房间，因此设置不会泄漏到其他用例。

生命周期必须通过宿主接口触发，而不是发送以下划线开头的普通事件：

```lua
ctx:playerLeave({index = 0, reason = 'test'})
ctx:playerJoin({index = 0, name = 'Player_0', reason = 'test'})
ctx:playerExit({index = 0, reason = 'test'})
```

这些接口不提供 JSON、分片、补发、请求 ID 或回执状态机。需要测试某个线协议时，应在测试 helper 中独立编解码，再显式逐帧调用 `send`。

## 全局存档辅助接口

`ctx` 可以直接读写当前房间接入的全局存档，用来播种“运维或其他房间已经写入”的数据、模拟他房广播与平台故障。房间以 `[no-ga]` 或 `room.global_archive_api = false` 创建时，调用这些方法会抛出测试错误。

```lua
ctx:gaSet('rank:1', '{"v":1}')           -- 字符串或整数；table 会按 JSON 编码
local raw = ctx:gaGet('rank:1')           -- string 或 nil
local removed = ctx:gaDel('rank:1')       -- 删除数
ctx:gaHmSet('mail:box', {['12'] = '{"id":12}'})
local fields = ctx:gaHGetAll('mail:box')  -- table<string, string>
local removed = ctx:gaHDel('mail:box', {'12'})
local acquired = ctx:gaLock('rank:1', 5000)   -- 以“别的房间”身份持有锁
ctx:gaUnlock('rank:1')
ctx:gaBroadcast('rank:changed', {b = 1; v = 2;})   -- 本房间收到 _msbroadcast；value 可为字符串或 table
ctx:setGaReplyDelay(0.5)                  -- 之后每个 MsGA* 回包延迟 0.5 秒送达
ctx:setGaFault({op = 'MsGAGet'; errnu = 2; count = 3;})   -- 接下来 3 次 MsGAGet 以 errnu=2 回包；op 缺省匹配全部操作，count 缺省持续生效
ctx:setGaFault(nil)                       -- 清除故障
local snapshot = ctx:gaDump()             -- {kv = {...}, hashes = {...}, locks = {key = token}}
```

这些方法直接操作存储，不经过 `_msga_reply`，因此是同步的；云脚本侧看到的仍然是异步回包。

## 同一用例的多房间与精确回包交错

`ctx` 本身代表默认房间。`ctx:createRoom(options?)` 创建另一个云脚本 VM，返回具有相同 `client`、生命周期、GA 辅助接口的房间上下文。新房间继承本用例脚本、bootstrap、模式、平台能力和超时；`players` 可完整替换玩家配置，字段与清单 `room.players` 相同，不能只给局部补丁。模拟不同在线玩家时应显式提供不同 GUID。

```lua
local other = ctx:createRoom {
    players = {{index=0, name='玩家B', platform={guid=9002}}},
}
local a, b = ctx:client(0), other:client(0)
CHECK_NE(ctx.roomId, other.roomId)

ctx:holdGaReplies('MsGAHmSet') -- 默认暂扣接下来的一个匹配回包，仅影响A房间
-- 向A发起业务请求，再等待 ctx:gaReplyState().held == 1。
-- 此时存储写入已经发生；B可读取、争锁或处理其他请求。
CHECK_EQ(other:gaHGetAll('rank:equip:1'), ctx:gaHGetAll('rank:equip:1'))
ctx:releaseGaReplies()        -- 投递原结果，不重新执行HmSet
-- 或 ctx:dropGaReplies()，模拟已经写入但回包永久丢失。
other:close()                 -- 主动结束B；A和共享GA继续存在
```

- 每个房间有独立玩家资产、事件队列、定时器和云脚本缓存；房间上下文的 `client:now()` 共用本 invocation 的单调时钟起点。MLS 请求 ID 可在不同房间独立递增。
- `createRoom` 返回前已完成 bootstrap、`_roomloaded` 及启动事件清理。子房间共享用例总超时，不因创建新房间重新获得一段完整用例时间。
- `close()` 首次关闭返回 true，重复关闭返回 false。关闭其他房间不清空 GA；需要持久化待处理状态的业务仍须自行实现，测试器不会替业务补报。
- 用例结束、断言中止、子房间启动失败时都会取消并回收已创建的所有房间；非主动关闭的子房间异常停止会使用例失败。失败日志带房间 ID，便于区分来源。
- `holdGaReplies(op, count?)` 只暂停指定房间的指定 GA 操作的**回包**，不暂停操作执行。`count` 为正整数，默认 1；已有闸门或暂扣结果未解决时禁止覆盖设置。
- `gaReplyState()` 返回 `{held, armed, calls}`；`calls[op]` 是本房间原生 GA 调用累计次数，不包含 `ctx:ga*` 直接操作。测试应等待明确状态并设置总截止时间，不靠固定短睡眠猜测操作顺序。
- `releaseGaReplies()` / `dropGaReplies()` 清除剩余闸门并处理全部暂扣结果，返回处理数量。释放保持暂扣顺序，丢弃不撤销已执行的存储变更；旧回包重试/忽略由真实云脚本负责。
- 既有 `setGaReplyDelay`、`setGaFault` 属于共享 GA 存储设置，会影响同一用例的所有房间。房间级交错使用上述闸门。前者延迟结果；后者在执行前拒绝操作，不能当作“已写入但丢回包”的测试。
- 闸门不会模拟延迟到达的存储执行，也不自动推进锁时钟；锁过期仍按模拟器单调实时时钟发生。不要以业务夹具替换房间时间后，声称已经验证平台锁自然过期。

本能力验证约定平台语义下的多房间业务行为，不证明真实平台一定具有同样的原子性和延迟边界。当前不是 Lua 堆内存或长局内存曲线测试工具。

## Reporter

- `console`：逐 invocation 输出结果、失败详情、测试输出和云日志尾部。
- `compact`：使用 `file:line` 单行失败格式，适合 Agent 和 CI。
- `json`：stdout 只输出一个 `schema_version = 1` 的 JSON 文档。

JSON 包含测试用例、SECTION invocation、断言、失败上下文、耗时和失败用例的云日志尾部。测试与数组顺序稳定，时间字段允许变化。

## LuaLS

可将 [mls-test-api.lua](mls-test-api.lua) 加入测试项目的 LuaLS 工作区，或按项目结构放入不参与测试发现的 `tests/meta/` 目录。

本测试框架只验证本地云脚本模拟行为，不能替代 Warcraft III 游戏内测试或真实平台验证。
